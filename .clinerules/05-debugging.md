# Debugging Rules

## Identify Root Cause

- Do not treat symptoms; find the underlying cause.
- Read error messages carefully.
- Trace the execution path to understand what is happening.

## Verify Assumptions

- Test assumptions before acting on them.
- Check data at each step of execution.
- Do not assume code works because it looks correct.

## Isolate Problems

- Narrow down the scope of the issue.
- Reproduce the problem with minimal inputs.
- Remove variables to find the exact cause.

## Apply the Smallest Fix

- Fix only what is broken.
- Do not refactor or rewrite surrounding code.
- Keep changes focused and minimal.

## Verify the Solution

- Confirm the fix resolves the issue.
- Check for side effects or regressions.
- Run relevant tests if available.

## Never Guess

- Do not make changes without understanding the problem.
- Do not apply fixes blindly.
- If the root cause is unclear, investigate further before making changes.
